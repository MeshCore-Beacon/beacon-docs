# Beacon roadmap after the November audit

This roadmap replaces the old assumption that the preview is the entire feature
stack. The current operator choice is **upstream dev plus audited fixes**, with
each bug fix in its own focused PR to dev. New features below are proposals, not
silently enabled preview behavior. The [audit](audit-20261116.md) explains the
findings; the [review map](review-map-20261116.md) is the merge queue.

## Stage 1 — land the correctness and work-bound fixes

Review independent changes by failure mode, not by repository-wide bundle.

| Work | Implementation | Acceptance |
| --- | --- | --- |
| Cache outage and late-miss races | Bounded cache operations, one shared DB fetch, leader recheck | Outage/cancellation/race regressions; cache failures do not multiply concurrent reads |
| Backfill pressure | Server-side write timeout, smaller initial slices, serialized writes, correct retry/watermark | PostgreSQL timeout/FK-race tests; no progress advancement on failure |
| JSON responses | Serialize before committing status | Invalid data yields structured 500, ordinary bytes unchanged |
| Stream reliability | Control/shape/expansion/write limits, explicit global gap notification | Normal reconnect stays usable; invalid region never broadens; queue drops are observable |
| Input and signal truth | Envelope cap, optional fields, finite numeric checks, independent denominators | Unknown does not become zero; explicit zero survives; omitted scopes do not erase history |
| Trace and route evidence | Structural validation, consumed hops, exact wire path, representation-bound cursors | No unsupported/unvisited promotion; old cursors remain compatible; matching web UI |
| Activity and clocks | Late-hearing query, pending-history refusal, correct sample cutoff | Raw oracle, rebuild readiness and insert/conflict regressions |
| Saved Atlas | Preserve old keys, current state wins, ownership boundaries unchanged | Local upgrade, empty state, blocked storage, account change and conflict tests |
| Client work | Map submission cap, coalesced chart resize, abortable mobile exchanges, stale-read cancellation | Measured worker-call bound; teardown cancellation; shared HTTP client remains usable |
| Channel clocks | Server receipt order, original timestamp displayed | Future-dated old message cannot remain last indefinitely |
| Operator evidence | Optional build identity, bounded Docker logs | Exact artifact identity is distinguishable from API version; all templates parsed |

Overlapping SQL and generated files must be regenerated against accepted dev when
each PR lands. Run the affected regression plus the complete required CI on that
new head. Do not merge a containing branch just to bypass a conflict between two
small fixes.

## Stage 2 — qualify the baseline for release

1. Freeze server/web/app source revisions and configuration. Record migrations,
   retained extra tables, asset/source hashes, runtime image and client floors.
2. Exercise an isolated restored database with representative packet types,
   observer counts, retention and re-hearings. Compare raw rows and read models.
3. Run quiet, burst and maintenance scenarios separately. Record throughput,
   queue drops, DB acquire waits, cache outcomes, timeout rate, CPU, RSS and I/O.
   Use a fixed fixture and identical query mix for before/after measurements.
4. Measure browser long tasks, layout/paint, worker submissions and frame-time
   distributions on a modest laptop and phone. A passing Node test is not GPU QA.
5. Test a previous application against the additive schema and verify restoration
   of the prior application/configuration without rolling back new observations.
6. Have the maintainer resolve dev1's public 502 and decide whether it remains a
   separate qualification environment. A second stale integration branch is not
   a substitute for a tested candidate.
7. Promote through dev to main/live under the maintainer's deployment process.
   No production performance/availability claim is based only on the Pi preview.

Suggested initial acceptance budgets, to calibrate on the agreed test host:
no synthetic fixture losses, no unresolved read-model discrepancy, no unbounded
retry loop, no more than one DB fetch per shared cold cache key within a server process, and no frame work
proportional to monitor refresh above the explicit rendering budget. Establish
latency/throughput thresholds from a baseline before declaring percentage gains.

## Stage 3 — native telemetry and accounts

The native upstream coordinator is the primary path. The separate collector is
not a second production backend to maintain indefinitely.

| Dependency | Concrete work | Release gate |
| --- | --- | --- |
| Preview addressing | Dedicated root hostname, or a separately reviewed subpath contract spanning API, firmware and mailed/portal links | One documented URL works end to end; disabled policy remains paused, never accidental fallback |
| Identity and delivery | Configure mail or portal credentials privately; verify domain and callback/origin rules | Controlled account can verify/reset/sign out; no leakage between accounts or servers |
| Trusted observers | Set request_observers explicitly; the final upstream default is all. Approve observer keys, broker/topic ACLs and supported firmware version | Unapproved observer never receives requested credentials; revoked/blocked observer stops receiving assignments |
| RF governance | Use native policy/owners, explicit direct/one-hop budgets and fail-closed leases | Lost connectivity, stale policy and server restart do not cause duplicate polling or flooding |
| Data transition | Export old samples; map source, channel, unit, time and missingness | Old data stays labeled historical/independent; no fabricated native trust or collapsed environmental channels |
| Mobile integration | Use the same coordination contract if companion collection is reintroduced | BLE/Wi-Fi lifecycle, Android notification controls, unplug/lock/background/reconnect and iOS limits physically qualified |
| Alerts | Controlled email/push delivery with deduplication, retries and expiry | Delivery receipts and user opt-out verified; evaluation-only success is insufficient |

Do not add a second polling scheduler to the app before the lease and identity
contract is agreed. A bridge that submits already observed measurements to one
coordinator is preferable to two autonomous clients racing the same repeater.

## Stage 4 — Topology as a separate product proposal

Retain the historical source for comparison, but rebuild the proposal against the
accepted dev head. Keep its API additions, renderer and qualification out of the
bug-fix merge queue.

- Start with one bounded server snapshot of observed links and explicit window,
  cap, freshness and provenance fields. Do not fetch thousands of route pages to
  construct a graph in a browser.
- Separate stable layout from live effects. Run expensive layout in a worker,
  reuse typed geometry, preserve camera state and update only changed elements.
- Make animation cost a budget: viewport culling, bounded active pulses,
  time-based motion and detail levels at different zooms. Aggregate bursts into
  labeled flows rather than silently claiming every packet is animated.
- Offer reduced motion and an explicit low-power mode. Stop hidden-tab work and
  avoid dense text measuring, shadows and source serialization every frame.
- Measure 1k/5k/10k-node scenes, resize, region changes, 24h loading, graph churn
  and a real busy stream. Report source submission rate separately from FPS.
- Public-message bubbles require verified decoded channel provenance, strict
  lifetime/count limits, no HTML interpretation and a user toggle.

Acceptance: no additional RF traffic, no repeated 24h request storm, no camera
reset on ordinary refresh, bounded memory after repeated region changes, and a
recorded frame-time distribution on the agreed low-end device.

## Stage 5 — enhancements worth testing

These ideas are ranked by user value and incremental cost. None authorizes a new
public endpoint, polling action or major dependency without a focused design.

| Proposal | Where it helps | Smallest credible implementation | Evidence/acceptance |
| --- | --- | --- | --- |
| Data freshness and coverage strip | Atlas, Analytics, Observers | Reuse generatedAt, rawFrom and rolledUntil; add per-family coverage rather than one global watermark | Rebuilds and retention gaps are distinguishable from zero traffic |
| Evidence drawer for a link | Map, Routes, later Topology | Existing cursor-bound route evidence, timestamps, hash widths, candidate ambiguity | Every displayed inference can be traced to retained reports; no implied delivery guarantee |
| Observer overlap/coverage matrix | Analytics | Hourly sets already stored; intersect distinct observer/region sets in bounded windows | Count definitions match raw fixtures; repeat hearing is not counted as a new packet |
| Network health timeline | Operator-only diagnostics | Align queue drops, broker connectivity, DB waits, rollup lag and API refusals by minute | Failure domains visible without channel contents or high-cardinality metrics |
| RF airtime budget view | Repeater details, native polling admin | Existing policy, claimed targets, recent trusted readings and actual packet airtime where present | Estimated versus observed airtime labeled; no model presented as channel occupancy truth |
| Clock and provenance lens | Channels, node details | Show sender clock offset alongside receipt order and evidence source | Original timestamps preserved; no mass deletion of suspicious records |
| Scope evidence matrix | Deferred scope proposal | Separate configured, reported, heard and uniquely repeated evidence; age and source per fact | Wildcard and allowed scopes coexist; absent default is not no scope; no MeshMapper dependency for worldwide mode |
| Repeater comparison | Atlas, Analytics | Shared-window comparisons of activity, signal distribution, trusted battery and freshness | Same denominator/window; missing signal never zero; no unsupported best-node score |
| Adaptive animation quality | Map, later Topology | Measure recent main-thread frame cost; lower submission/detail budget within explicit limits | Stable motion timing; visible reduction in load without hiding the existence of traffic |
| Snapshot and replay laboratory | Maintainer tooling | Sanitized fixture capture and deterministic replay against an isolated DB | No replay into live MQTT; fixed seed/window/source and raw-count oracle |
| Cache effectiveness diagnostics | Operator-only | Bounded hit/miss/invalid/error counters with DB timing delta | No node/key labels; distinguish cache outage from slow database |
| Release comparison page | Operator docs | Generate version/source/schema/feature matrix from receipts | Exact commits and flags; unknown runtime source shown as unknown |

## Database and scaling ideas requiring measurement

1. **Per-family coverage:** record which hours each read model has actually built.
   Dirty work should carry a generation/family so adding one model does not imply
   old completed hours cover it. Validate rollback and late-observation handling.
2. **Query cost visibility:** enable private pg_stat_statements and timing during
   an operator-approved maintenance window. Capture deltas, redact SQL text and
   identifiers, then prioritize total time and p95 rather than query count alone.
3. **Storage/WAL budget:** compare vacuum/retention cadence, write amplification
   and checkpoint I/O during bursts. Avoid global work_mem increases or blanket
   index removal on a shared small host.
4. **Retention architecture:** consider partitioning only when measured retention
   deletes or index churn justify its migration and uniqueness costs. Design
   cross-partition deduplication, foreign keys and rollback before implementation.
5. **Read projections:** prefer compact hourly/link projections already needed by
   clients over repeatedly shipping raw route arrays. Every projection needs
   coverage, cap and provenance semantics plus a raw-data oracle.
6. **Resilience:** introduce fault-injection fixtures for Redis outages, slow DB
   acquisition, broker reconnects, malformed input and full fanout queues. Keep
   failure injection isolated from public instances.

## Maintenance ownership

The organization owns acceptance, releases and production operation. Contribution
forks own preview artifacts and their receipts. The operator keeps secrets and
backups private. Reviewers need one current index with each fix's exact PR, base,
dependency and test result. Superseded broad drafts are closed with replacement
links; deferred features stay visibly separate from fixes. Do not request review
or merge on the strength of stale CI, a branch name or an old screenshot.
